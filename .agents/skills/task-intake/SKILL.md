# task-intake

Capture objective, current behavior, desired behavior, scope/non-scope, constraints, acceptance criteria, known files, external dependencies, risk indicators and unknowns. Keep product decisions with the human. Save structured tasks using `tasks/TASK_TEMPLATE.json` when durable work is needed.

<!-- PRODUCT_DISCOVERY_V1:START -->
Do not force a broad product idea, multi-feature request or materially ambiguous goal into one task. Use `idea-to-work` first when the request is larger than one independently verifiable outcome or when product gaps materially affect scope, behavior, architecture, risk or success criteria. Use `sprint-planning` only after executable tasks are approved.
