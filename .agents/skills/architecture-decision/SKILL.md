# architecture-decision

Use for architectural choices with material alternatives or long-lived consequences.

1. State context and constraints.
2. Enumerate viable alternatives, including status quo.
3. Compare correctness, reversibility, operability, security, cost and migration burden.
4. Separate facts from assumptions.
5. Record decision, consequences, rollback/migration and review trigger.
6. Require human approval for irreversible R3 choices.

Write the ADR under `docs/architecture/decisions/` only when the task authorizes documentation changes.
